# ロール別ユーザーガイド (USE CASES)

## 概要

305-hrl-nippou-app の 4 ロール (general / manager / executive / admin) ごとの典型的な利用シナリオと使う画面・機能をまとめる。

---

## ロール早見表

| ロール | 主な目的 | アクセス可能な主要画面 |
|---|---|---|
| general | 自分の日報作成・顧客記録・上長への報告 | /today, /reports, /households, /calendar, /search, /settings, /opportunities, /policies |
| manager | 部下日報レビュー・コメント・差し戻し | + /dashboard (部下絞り込み) |
| executive | 全社俯瞰・経営判断 | + /dashboard (全社統計), /admin (読取専用) |
| admin | ユーザー・チーム・組織編成管理 | + /admin (フル機能) |

---

## 1. general (一般社員) — 営業担当の 1 日

### ペルソナ

霧島 遥さん。保険営業担当。毎日世帯訪問 + 日報作成。担当世帯の世帯員構成・健康情報を把握し、保険提案に活かすことが日課。

### 朝 (出社時)

1. `/today` を開く → 昨日承認された TODO / 当日予定タイムライン確認
2. 朝の気分・天気 (☀️ 晴れ / 🌤 やや曇り / ☁️ 曇り / 🌧 雨) を選択
3. ヘッダーに「上長への合図」(💬 相談したい / 👂 聞いて / 👍 大丈夫) があれば選ぶ
4. 当日の予定タイムブロックを追加 (訪問・電話・社内業務 等)

### 訪問前準備 (出発前・Phase 1)

4.5. `/households` で訪問予定の世帯を検索 → 世帯詳細画面を開く (旧: `/customers`からリダイレクト)
   - 「👨‍👩‍👧 世帯員」セクションで**世帯員構成**を確認（続柄・生年月日・健康情報）
   - 世帯主と家族構成（spouse/child 等）を頭に入れてから訪問
   - `familyMemo` で「配偶者あり・子 2 名」等のメモを再確認

### 昼 (訪問先で)

5. `/households` で訪問予定の世帯を検索 → 詳細画面で過去訪問履歴・メモ確認
6. 訪問後、`/today` の実績タイムライン側に「実績ブロック」を追加 (顧客紐付け + メモ)
   - 顧客選択欄は **コンボボックス形式**: 顧客名・エリア・タグを入力するだけで候補を絞り込み可能
   - お気に入り (⭐) に登録した顧客は一覧の上位に表示される
   - 弗 30 日以内に接触した顧客には 🕒 アイコンが付き、自動的に上位に表示される
6.5. **訪問記録時にステージを進める (Phase 2 — 日報内ステージ進捗更新 UX)**:
   - 実績ブロック追加時、世帯選択後に「商談案件 (任意)」欄が出現
   - 例: 「田中家」を選択 → 「田中家 ライフプラン見直し」の商談案件が表示される
   - 案件を選択すると「→ ステージを変更する（現在: 設計書提示）」ボタンが展開
   - 「検討中」を選んで「ステージを更新」をクリック → `proposal → negotiation` へ即時更新
   - ブロック保存と同時に `stageHistory` に自動追記、localStorage に永続化
7. 顧客からのお褒め / 改善要望は「お褒め記録」セクションに追記

### 夕方 (帰社時)

8. `/today` 右ペインで TODO の達成状況を更新 (チェック / 期限延長)
9. 「夕の気分」を入力
10. **コメントセクション**で上長宛に質問・補足を投稿 (緑系アバター + 「↑ 上長宛」バッジ)
11. **日報提出** ボタンで提出 (status: submitted)

### 月末

12. `/search` で過去日報を月単位で検索 → 振り返り
13. `/households` で世帯情報の整理 (タグ追加・メモ更新)

### Opportunity 受注 → 契約発行 → 証券番号入力フロー (Phase 3)

14. `/opportunities` の該当案件を開く（ステージ: ニーズ分析〜申込書記入）
15. 「🎉 契約発行（受注）」ボタンをクリック → `QuickPolicyIssueModal` が開く
   - 「提案商品」一覧に内容を確認（`ProposalProducts` の商品名・保険会社・月払）
   - 「発行する」ボタンをクリック → `Policy` が各提案商品から 1:1 で自動生成 (`status: pending`)
   - Opportunity が自動的に `stage: issued` / `status: won` に遷移
16. `/policies` で生成された契約を確認 → 該当契約を開く
17. 「証券番号を入力」ダイアログ → 証券番号 + 契約開始日を入力して「有効化」をクリック
   - `status: pending` → `status: inforce` に昇格
   - ステータス履歴に `'証券番号: <番号>'` メモの履歴が自動記録される

### 世帯保障マトリクス確認 → 保障漏れ発見 → 新規 Opportunity 作成 (Phase 3)

18. `/households/:id` で訪問予定の世帯を開く
19. 「🛡️ 保障マトリクス」セクションを確認
   - 行 = 世帯員（Person）、列 = 保障種別 (死亡/入院/がん/就業不能/介護/貯蓄)
   - `-`（保障なし）のセルが「保障漏れ」のサイン
   - 世帯主に死亡保障がなければ赤警告バナーが自動表示
20. 保障漏れを発見したら `/opportunities` で新規商談案件を作成
   - 「+ 新規案件」ボタンから `QuickOpportunityModal` を開く
   - 「子どもがれん保険なし」等、保障漏れをエビデンスにした箋道をスタート

### 制限事項

- `/admin` → Forbidden
- 他人の日報詳細を開いてもコメント投稿不可
- 付帯情報あり世帯 (🔗 バッジ) の削除不可

### 法人世帯について

`type === 'corporate'` の法人世帯（山田工業・テクノ精工など）は Phase 1 以降も存続する。法人世帯の `Person` には `relation: 'other'` で担当者（代表取締役など）を登録する運用とする。`familyMemo` フィールドは法人世帯では通常空で問題ない。

## 2. manager (上長) — チーム管理職の 1 日

### ペルソナ

佐藤 健一さん。営業1課マネージャー。チームメンバー 3 名の進捗管理。

### 朝

1. `/dashboard` を開く → 部下の提出状況・遅延・気分グラフ確認
2. 未提出メンバーがいれば `/notifications` で確認 → リマインダー送信

### 昼

3. 提出済日報を `/reports/:date?user=:userId` で順次開く
4. **コメント** セクションで部下にフィードバック (青系アバター + 「コメント追加」)
5. 内容に不備があれば「差し戻す」ボタン (理由必須)
6. 部下から `↑ 上長宛` バッジ付きコメントが来ていれば YES/NO 返答 or テキスト返信

### 夕方

7. `/dashboard` で当日の全員提出状況を確認
8. 確認済日報を「承認」(status: confirmed) でクローズ
9. お褒め記録は週次でまとめ社内共有

### 商談パイプライン確認 (Phase 2)

10. `/opportunities` を開く → チームメンバーの商談案件一覧をロールフィルターで確認
    - ステージ別の進捗（アプローチ〜査定中）が一目でわかる
    - 「次アクション期日」が近い案件を優先的に確認
    - 部下の案件詳細を開き「活動履歴」タブで最近の訪問記録を確認

### 部下世帯の契約一覧確認 (Phase 3)

11. `/policies` を開く → チームメンバー担当の契約一覧を全俦瞰
   - `status` フィルターで「申込中 (pending)」を絞り込み— 未有効化の契約を確認
   - 証券番号未入力の契約があれば担当者に入力を促す
   - 年間更新令月午前の契約も確認 (「次回更新」列)

### 制限事項

- `/admin` → Forbidden
- 自分のチーム外メンバーの日報も閲覧可能だがコメント可能 (運用上自重)

## 3. executive (経営者) — 経営層の 1 週間

### ペルソナ

鈴木 美咲さん。事業統括役員。全社目線で組織パフォーマンスを把握。

### 平日朝

1. `/dashboard` で全社統計確認 (提出率・気分推移・チーム比較)
2. 気になる部門があれば `/reports/:date?user=:userId` で個別レビュー
3. **コメント** セクションで部下日報に経営目線コメント追加可能

### 週中

4. `/admin` を **読取専用** で開く (黄色バナー表示)
   - 👥 ユーザー一覧で組織図 (上長関係) 確認
   - 🏢 チーム編成・上長配置を把握
   - 📜 監査ログで管理操作履歴を確認
5. 編集が必要な場合は admin (高田さん) に依頼

### 月次

6. お褒め記録を全社でまとめ表彰候補抽出
7. `/dashboard` で月次比較

### 商談全社一覧 (Phase 2)

8. `/opportunities` を開く → 全担当者の全案件を全社俯瞰
   - `status: open` の案件のみ表示し、進捗中のパイプラインを把握
   - ステージ別フィルターで「引受査定中」案件の件数を確認
   - 合計月払額を確認し、見込み売上のサマリーを把握

### 契約ステータス分布確認 (Phase 3)

9. `/dashboard` を開く → **契約ステータス分布**グラフで全社の契約状態を俯瞰
   - inforce (有効中) / pending (申込中) / lapsed (失効) 等 7 ステータスの帯円グラフ
   - **保険会社別契約数**パネルで保険会社ごとの契約分布を把握
   - 失効・解約契約の割合が高い保険会社があれば経営視点で検討

### 制限事項

- `/admin` で編集・招待・削除ボタンは非表示 (黄色バナーで明示)
- ユーザー追加・チーム編成変更は admin 経由

## 4. admin (管理者) — システム管理者の運用

### ペルソナ

高田 一郎さん。情シス兼任。組織・ユーザーマスタの管理が主務。

### 入社・異動時

1. `/admin` → 👥 ユーザータブで「招待」→ 氏名・メール・ロール・チーム指定
2. 入社者が初回ログイン → ロール本来の画面に遷移
3. 異動者は「編集」ボタンで teamIds 変更

### 組織変更時

4. 🏢 チームタブで「編集」→ メンバー追加・上長指定 (チェックボックス)
5. 新チーム作成 → ユーザーから所属付与
6. 旧チーム削除 (メンバーは自動でチーム外に)

### 退職時

7. ユーザー行の「無効化」→ status: inactive (データは保持)
8. 完全削除はせず履歴を残す

### 監査

9. 📜 監査ログタブで操作履歴を確認 (ログイン成功/失敗 + ロール変更 + チーム編成変更)
10. 不審な失敗ログイン (P1 ロック発動) があれば対象ユーザーに連絡

### 制限事項

- なし (フル権限)
- ただし破壊的操作 (チーム削除等) は確認ダイアログ + 名前入力で誤操作防止
